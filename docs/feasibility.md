# ให้ Feasibility วิ่งเอง

ทุกวันนี้ชีต Feasibility เป็นไฟล์ที่ต้องไปกรอกตามหลังการขาย
ในผังกระบวนการที่ทีมเขียนเอง มันอยู่ปลายน้ำของใบวางบิล
แปลว่ามันควรเป็น **ผลลัพธ์** ไม่ใช่ตารางที่ต้องอัปเดต

## ปัญหาที่ต้องแก้ก่อน — คำว่า "Actual" มีสามความหมาย

ชีตมีคอลัมน์ Actual ช่องเดียว แต่ตอนกลางฤดูขายมีตัวเลขสามตัวที่ต่างกันมาก

| ตัวเลข | หมายความว่า | ใช้ตอบคำถามอะไร |
|---|---|---|
| ปิดได้ | เซ็นแล้ว ตกลงราคาแล้ว | ขายทันเป้ามั้ย |
| เงินเข้าแล้ว | เข้าบัญชีจริง | มีเงินจ่ายซัพพลายเออร์มั้ย |
| ค้างรับ | ปิดได้ ลบ เงินเข้า | ต้องไปตามเก็บใคร |

ยุบสามตัวนี้เป็นช่องเดียวเมื่อไหร่ ก็ตอบคำถามได้แค่ข้อเดียว
`v_deal_value` แยกทั้งสามออกมาจากข้อมูลชุดเดียวกัน

## กลไก

บรรทัดงบฝั่งรายได้ประกาศว่าตัวเองกินยอดมาจากไหน

    budget_line.source_kind = 'booth_type'
    budget_line.source_ref  = 'gold'

พอตั้งเป็น auto แล้ว `ac_total` ไม่ต้องกรอกมือ มันมาจาก `v_income_by_type`
ซึ่งนับจาก `deal_item` ที่ผูกกับบูธจริง

เส้นทางของตัวเลขหนึ่งก้อน

    เซลล์กดจองบูธบนผัง
      -> deal สถานะ booking, deal_item ผูกบูธ, booth สถานะ held
      -> ใบเสนอราคา            document kind = quotation
      -> ลูกค้าตกลง            deal สถานะ confirmed, deal_total = ราคาที่ตกลงจริง
      -> ใบวางบิล              document kind = billing_note
      -> มัดจำเข้า 50%          payment kind = deposit, paid_at = วันนี้
      -> Feasibility ขยับเอง   v_income_by_type -> budget_line.ac_total

ไม่มีขั้นตอนไหนต้องเปิดชีตไปพิมพ์ซ้ำ

## ตัวเลขที่จะเปลี่ยนไปทันทีที่ทำ

**ส่วนลดจริงรายชั้น** วันนี้ชีตหักก้อนเดียวที่ 40%
ของจริงปี 2026 คือ 36% เฉลี่ย แต่ Title 0% · Gold 54% · Silver 23%
`v_deal_value.discount_pct` คำนวณให้รายดีล รวมขึ้นมาเป็นรายชั้นได้

**บูธแลกของไม่ปนกับส่วนลด** 18 จาก 111 ดีลปี 2026 ราคา 0 บาท
`deal.settlement` แยก barter ออกจาก cash ตัวเลขส่วนลดเลยไม่บวมโดยไม่มีความหมาย

**ค่าคอมคิดรายดีล** งบตั้ง Sales Agent Commission 10–15% ของยอดรวม
พอมี `deal.owner_id` กับ `deal.agent_id` ก็คิดตามคนที่ปิดได้จริง
และแยกบูธที่ Torpenguin ให้ฟรีออกจากฐานคำนวณ

**pacing** `v_event_pace` ตอบได้ว่าวันนี้ขายไปเท่าไหร่เทียบแผน
ซึ่งมีค่ากว่าการเทียบยอดตอนจบงาน เพราะเราจัดงานเดิมซ้ำทุกปี

## ที่ยังไม่วิ่งเอง

ฝั่งรายจ่ายทั้งหมด — ค่าสถานที่ เวที การตลาด ทีมงาน ยังต้องกรอกใน `budget_line`
วิ่งเองได้เฉพาะฝั่งรายได้ เพราะมันมาจากบูธและเวทีโดยตรง

ยกเว้นสองรายการที่คำนวณได้ ต้นทุนโครงสร้างบูธกับกระแสไฟบูธ
เพราะผูกกับจำนวนบูธที่ขายไปตรง ๆ (shell scheme 2,500 · 2x2 ที่ 1,800 · ไฟบูธ 750)

# หน้าเป้าและ run rate

แยกจาก Feasibility เพราะตอบคนละคำถาม
Feasibility ตอบว่า "งานนี้กำไรมั้ย" หน้านี้ตอบว่า "วันนี้ตามทันมั้ย"

## ตัวเลขสี่ตัวที่ต้องเห็นพร้อมกัน

| ตัวเลข | ที่มา |
|---|---|
| เป้ารายได้ | `event.revenue_goal` ของ TRC 2026 คือ 13,066,200 (ราคาตั้ง 21,777,000 หัก 40%) |
| ปิดได้แล้ว | รวมดีลที่สถานะตั้งแต่ booking ขึ้นไป |
| เงินเข้าแล้ว | `v_deal_value.received` |
| ยังขาดอีก | เป้า ลบ ปิดได้ |

แล้วหารด้วยวันที่เหลือจนถึงวันงาน ได้เป็น **ต้องปิดให้ได้วันละเท่าไหร่**
แปลงเป็นจำนวนบูธด้วยราคาเฉลี่ยต่อบูธที่ปิดได้จริง ไม่ใช่ราคาตั้ง
เพราะเซลล์ทำงานเป็นบูธ ไม่ได้ทำงานเป็นบาท

## ข้อจำกัดที่ต้องยอมรับตอนนี้

**ยังบอกไม่ได้ว่าตอนนี้ขายเร็วแค่ไหน** ชีตไม่ได้บันทึกว่าปิดดีลแต่ละรายวันไหน
หน้านี้จึงบอกได้แค่ "ต้องทำเท่าไหร่" ไม่ใช่ "ทำได้จริงเท่าไหร่"

`deal.won_at` มีไว้เก็บเรื่องนี้ พอเก็บครบหนึ่งฤดูขาย จะเทียบยอด ณ วันเดียวกันกับปีก่อนได้
ซึ่งเป็นตัวเลขที่มีค่าที่สุดสำหรับงานที่จัดซ้ำทุกปี — บอกได้เร็วที่สุดว่าปีนี้ช้ากว่าปีก่อนมั้ย
เร็วกว่ารอดูยอดตอนจบงานเป็นเดือน

**วันงานต้องมีจริง** ถ้า `event.start_date` ว่างหรือผ่านไปแล้ว run rate คำนวณไม่ได้
หน้าจอบอกตรง ๆ แล้วให้ใส่วันใหม่ แทนที่จะโชว์ตัวเลขที่ไม่มีความหมาย
