# สิทธิ์การเข้าถึง

ระบบภายใน เข้าด้วยคำเชิญเท่านั้น ไม่มีหน้าสมัครเอง
แอดมินเชิญด้วยอีเมล ผู้ใช้ตั้งรหัสผ่านครั้งแรกแล้วบังคับเปลี่ยน

## ตารางสิทธิ์

`read` ดูได้ · `write` แก้ได้ · `approve` อนุมัติได้ · `—` ไม่เห็นเลย

| โมดูล | เซลล์ | หัวหน้าเซลล์ | บัญชีการเงิน | การตลาด | ปฏิบัติการ | ผู้บริหาร | แอดมิน |
|---|---|---|---|---|---|---|---|
| ผังบูธ | write | write | read | read | write | read | write |
| ดีล ลูกค้า | write (เฉพาะของตัวเอง) | write | read | read | read | read | write |
| ราคาตั้ง ส่วนลด | read | approve | read | — | — | approve | approve |
| ใบเสนอราคา ใบวางบิล | write (ของตัวเอง) | write | write | — | — | read | write |
| การชำระเงิน | read (ของตัวเอง) | read | write | — | — | read | write |
| **Feasibility งบประมาณ** | **—** | **—** | write | — | — | read | write |

## เหตุผลของเส้นที่ขีดไว้

**เซลล์ไม่เห็น Feasibility** เซลล์ต้องรู้ราคาตั้งเพื่อไปขาย และต้องเห็นดีลของตัวเอง
แต่ต้นทุน กำไรขั้นต้น และยอดรวมทั้งงาน ไม่ได้ช่วยให้ขายดีขึ้น
และเป็นข้อมูลที่ถ้าหลุดออกไปตอนเจรจา จะเสียเปรียบทันที

**หัวหน้าเซลล์ก็ยังไม่เห็น** ตั้งใจให้เป็นแบบนี้ก่อน หัวหน้าเซลล์เห็นยอดขายทุกคนและอนุมัติส่วนลดได้
ซึ่งพอสำหรับงานที่ต้องทำ ถ้าทีมอยากให้เห็น เปลี่ยนแถวเดียวในตาราง `role_permission`

**บัญชีการเงินแก้ผังไม่ได้** เห็นตัวเลขครบ ออกเอกสารได้ บันทึกเงินเข้าได้
แต่ย้ายบูธหรือเปลี่ยนสถานะบูธไม่ได้ เพราะนั่นคือเรื่องของคนขายกับคนคุมผัง

**ผู้บริหารอ่านอย่างเดียว** เห็นทุกอย่าง แก้ไม่ได้ ลดโอกาสแก้ตัวเลขโดยไม่ตั้งใจ
และทำให้ร่องรอยการแก้ไขอ่านง่ายขึ้น

## ขอบเขต own กับ all

`role_permission.scope` บอกว่าเห็นเฉพาะของตัวเองหรือทั้งงาน
ตอนนี้ตั้งให้เซลล์เป็น `own` สำหรับดีล — เห็นบูธของคนอื่นบนผังว่ามีคนถือแล้ว
แต่ไม่เห็นชื่อลูกค้าและเบอร์ติดต่อ ยังต่อคิวได้ตามปกติ

**ข้อนี้ยังไม่ได้ยืนยันกับทีม** ถ้าอยากให้เซลล์เห็นดีลกันหมด
เปลี่ยน `(sales, deal)` จาก `own` เป็น `all`

## สิทธิ์เก็บเป็นข้อมูล ไม่ฝังในโค้ด

ตาราง `role` กับ `role_permission` ถูก insert ค่าเริ่มต้นไว้ในสคีมา
เปลี่ยนสิทธิ์คือแก้ข้อมูลหนึ่งแถว ไม่ต้องแก้โค้ดและไม่ต้องขึ้นระบบใหม่
ซึ่งจำเป็นกับทีม 15–20 คนที่หน้าที่เปลี่ยนได้ระหว่างฤดูขาย

## สิ่งที่ต้องมีตอนทำจริง

- เก็บแฮชรหัสผ่าน ไม่เก็บรหัสผ่าน (`app_user.password_hash`)
- token ล็อกอินเก็บเป็นแฮชเช่นกัน (`auth_session.token_hash`) เพิกถอนได้รายเครื่อง
- นับความพยายามล็อกอินที่ผิด (`login_attempt`) แล้วหน่วงเวลาเมื่อผิดถี่
- ตรวจสิทธิ์ที่ฝั่งเซิร์ฟเวอร์ทุกครั้ง การซ่อนปุ่มบนหน้าจอไม่ใช่การกันสิทธิ์
- คนคนเดียวสิทธิ์ต่างกันได้ในแต่ละงาน ผ่าน `user_event.role`
