# โครงตั้งต้น

## 1. ข้อสรุปจากการสำรวจตลาด

ตลาดแยกเป็นสามกลุ่มที่ไม่ทับกัน

| กลุ่ม | ใคร | เอามาใช้ได้ |
|---|---|---|
| ขายบูธ + ผังงาน | Map Your Show · A2Z · ExpoFP · EXPOCAD · Map D | วงจรสถานะบูธ · การจองที่มีวันหมดอายุ · ผังสีตามวันเข้างาน · รายงาน pacing |
| งบและสัญญา | Momentus (เดิม Ungerboeck) | โครงงบประมาณแผน–จริง · ใบเสนอราคาจากเทมเพลต · pipeline การขาย |
| คนเข้างาน | Cvent · Swapcard · Eventbrite | ไม่เกี่ยวกับเรา ตัดทิ้ง |

**ข้อสังเกตที่ทำให้ขอบเขตเล็กลงมาก** — แพลตฟอร์มพวกนี้ออกแบบมาสำหรับงานที่ขายบูธ
หลายร้อยบูธและให้ผู้ออกบูธล็อกอินเข้ามาทำงานเอง ฟีเจอร์ครึ่งหนึ่งที่เขาขาย
(แอปผู้เข้าชม · matchmaking · badge scan · exhibitor portal) อยู่นอกขอบเขตของเรา
สิ่งที่เราต้องการใกล้กับ **CRM + คลังสินค้า + งบประมาณ ที่มีมุมมองเป็นแผนผัง** มากกว่า

## 2. สิ่งที่ตัดสินใจแล้ว

| เรื่อง | เลือก | ผลต่อการออกแบบ |
|---|---|---|
| ผู้ใช้ | ภายในก่อน ออกแบบเผื่อ portal | แยก role ตั้งแต่วันแรก แยกฟิลด์ที่คนนอกจะเห็นออกจากฟิลด์ภายใน ยังไม่ทำล็อกอินคนนอก |
| เงิน | เชื่อมโปรแกรมบัญชีที่ใช้อยู่ | ระบบนี้เป็นเจ้าของ "ดีลและกำหนดชำระ" ไม่ใช่เจ้าของ "เลขทางบัญชี" ต้องกันช่องเก็บเลขอ้างอิงจากโปรแกรมบัญชี |
| ผังงาน | มีไฟล์ CAD (DWG/AI) | แปลงเป็น SVG ครั้งเดียวต่องาน ผูก id ของบูธเข้าฐานข้อมูล ไม่ต้องสร้างเครื่องมือลากวางเอง |
| เริ่มที่ | ขายบูธ + ผังงาน | โมดูลอื่นห้อยจากตารางเดียวกัน ทำทีหลังได้โดยไม่ต้องรื้อ |

## 3. แกนของระบบ

ทุกอย่างห้อยจากสองตารางนี้

### booth — พื้นที่ขาย

รหัสบูธ · งาน · โซน · ขนาด (กว้าง x ลึก) · ตารางเมตร · ราคาตั้ง · พิกัดบนผัง · สถานะ

วงจรสถานะ ลอกจากที่อุตสาหกรรมใช้กัน

    ว่าง -> จองไว้ (มีวันหมดอายุ) -> เซ็นสัญญา -> มัดจำแล้ว -> จ่ายครบ
              |
              +-- หมดอายุ -> กลับไปว่าง

บวกสถานะ "บล็อก" สำหรับพื้นที่ที่ไม่ขาย เช่น ทางเดิน เวที ห้องน้ำ จุดบริการ

**กติกาที่ต้องมีตั้งแต่แรก** การจองต้องมีวันหมดอายุและปล่อยคืนเองเมื่อไม่จ่ายมัดจำตามกำหนด
มาตรฐานที่งานต่างประเทศใช้คือมัดจำ 50% ภายใน 30 วันหลังเซ็นสัญญา
ถ้าไม่มีข้อนี้ ผังจะเต็มไปด้วยบูธที่จองไว้แต่ไม่มีเงินเข้า

### deal — การขาย

ลูกค้า · งาน · ประเภท (บูธ หรือ สปอนเซอร์) · มูลค่า · ส่วนลด · เงื่อนไขพิเศษ ·
เซลล์ที่ดูแล · สถานะ · เลขอ้างอิงจากโปรแกรมบัญชี

    ติดต่อ -> เสนอราคา -> ต่อรอง -> ส่งสัญญา -> ปิดการขาย
                                        |
                                        +-- ยกเลิก

หนึ่ง deal ผูกได้หลายบูธ (ลูกค้าเจ้าเดียวจองสามบูธติดกัน)
และ deal สปอนเซอร์ไม่ผูกบูธเลยก็ได้

## 4. โมดูลที่ห้อยจากแกน

| ลำดับ | โมดูล | ทำอะไร |
|---|---|---|
| 1 | ขายบูธ + ผัง | คลิกบูธบนผัง เห็นสถานะ ผูกดีล บันทึกมัดจำและเงื่อนไข |
| 2 | งบประมาณ | ตั้งงบรายหมวด เทียบกับจ่ายจริง รายได้จริงเทียบเป้า กำไรต่องาน |
| 3 | สปอนเซอร์ | แพ็กเกจ สิทธิประโยชน์ที่สัญญาไว้ เช็กว่าส่งมอบครบมั้ย |
| 4 | การตลาด | แผน owned และ paid แยกช่องทาง งบที่ใช้ ผลที่ได้ |
| 5 | ก่อสร้าง | ตารางเข้างาน ผู้รับเหมาของแต่ละบูธ เอกสารที่ต้องส่ง เช็กลิสต์ |

## 5. สิ่งที่ควรลอกมาตรง ๆ

- **หมดอายุการจองอัตโนมัติ** กันผังเต็มด้วยบูธที่ไม่มีเงิน
- **ผังสีตามวันเข้างาน** ใช้ผังเดียวกันเปลี่ยนโหมดสี ทีมก่อสร้างอ่านจากผังเดิมได้
- **รายงาน pacing** ยอดขาย ณ วันนี้ เทียบกับปีที่แล้ว ณ วันเดียวกัน ไม่ใช่เทียบยอดสิ้นปี
  เพราะเราจัดงานเดิมซ้ำทุกปี ตัวเลขนี้บอกได้เร็วที่สุดว่าปีนี้ช้ากว่าปีก่อนมั้ย
- **งานเป็นเทมเพลตที่โคลนได้** Restech ปีหน้าเริ่มจากการโคลนปีนี้ ไม่ใช่เริ่มจากศูนย์

## 6. ยังไม่รู้ ต้องถาม

- ใช้โปรแกรมบัญชีตัวไหน (PEAK / FlowAccount / Xero / อื่น) และมี API ให้เชื่อมมั้ย
- แต่ละงานมีกี่บูธ กี่โซน และราคากี่ระดับ
- ทีมที่จะใช้ระบบมีกี่คน แบ่งหน้าที่ยังไง (เซลล์ / การตลาด / ปฏิบัติการ / ผู้บริหาร)
