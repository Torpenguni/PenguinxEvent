# อีเมลและการแจ้งเตือน

## สวิตช์ก่อนอย่างอื่น

งานนี้มีผู้ออกบูธจริง 56 รายที่จ่ายเงินแล้ว เมลที่ยิงออกไปเรียกกลับไม่ได้
ระบบจึงตั้งค่าเริ่มต้นเป็น **ไม่ส่ง** และต้องพิมพ์คำว่า `true` เป๊ะ ๆ ถึงจะส่งจริง

```
MAIL_ENABLED=false      # อย่างอื่นทั้งหมดคือไม่ส่ง
MAIL_REDIRECT_TO=       # ใส่กล่องตัวเอง เมลทุกฉบับจะวิ่งมาที่นี่แทนผู้รับจริง
```

ปิดอยู่ไม่ได้แปลว่าไม่มีอะไรเกิดขึ้น ทุกฉบับยังถูกบันทึกใน `mail_log` เป็น `skipped`
พร้อมชื่อผู้รับตัวจริงและเหตุผล จึงตรวจได้ว่า "ถ้าเปิด จะมีเมลออกไปหาใครบ้าง"

ตอนบูตเซิร์ฟเวอร์จะพิมพ์บรรทัดเดียวบอกสถานะ เช่น

```
อีเมล: ยังไม่ส่งจริง (ยังไม่ได้ตั้ง RESEND_API_KEY และ MAIL_FROM) ...
อีเมล: ส่งได้ จาก Penguin X <noreply@penguinx.co> (เปลี่ยนผู้รับทุกฉบับไปที่ test@…)
```

มีบรรทัดนี้เพราะ "ยังไม่ได้ตั้งค่า" กับ "พิมพ์ชื่อ env ผิด" หน้าตาเหมือนกันเป๊ะตอนรัน

## ทุกอย่างผ่าน apps/api/src/lib/mail.js

route ไหนก็ตามที่อยากส่งเมล เรียก `sendMail()` เท่านั้น ห้ามเรียก Resend ตรง ๆ
เพราะสามอย่างนี้ต้องเกิดทุกครั้ง มีแถวใน `mail_log` เสมอ · สวิตช์ทำงานเสมอ ·
`MAIL_REDIRECT_TO` ทำงานเสมอ

`sendMail` คืนสถานะจริงกลับมา (`sent` `failed` `skipped`) และผู้เรียกต้อง `await`
ไม่มี fire-and-forget ในระบบนี้ เมลที่ส่งไม่สำเร็จแล้วเงียบ แย่กว่าเมลที่ไม่ได้ส่ง
เพราะทีมเชื่อไปแล้วว่าลูกค้าได้รับ

## ตาราง mail_log

เขียนอย่างเดียวไม่แก้ เหมือน `audit_log` ตอบคำถามเดียวคือ
"ตกลงคนนี้ได้รับเมลหรือยัง" ไม่ใช่ "โค้ดเรียกฟังก์ชันส่งหรือยัง"

คอลัมน์สำคัญ `to` คือผู้รับที่ตั้งใจส่งถึงเสมอ แม้ตอนทดสอบที่เมลถูกเปลี่ยนปลายทาง
ปลายทางจริงตอนนั้นอยู่ในคอลัมน์ `redirected_to` แยกกัน

## สิ่งที่ทำได้แล้ว

| เรื่อง | ใครกด | ปลายทาง |
|---|---|---|
| เชิญคนนอกดูงาน | `POST /api/shares` | ลิงก์รับคำเชิญอายุ 30 วัน |
| เชิญทีมงานเข้าระบบ | `POST /api/users/invite` | ลิงก์ตั้งรหัสผ่านอายุ 7 วัน |
| เตือนผู้ออกบูธ | cron วันละครั้ง หรือ `POST /api/mail/reminders/send` | เมลรวมฉบับเดียวต่อบริษัท |
| เมลติดตามดีล | `POST /api/deals/:id/emails` | ผู้ติดต่อของบริษัทนั้นเท่านั้น |

หน้าจอสำหรับสองข้อแรกอยู่ที่ **ผู้ใช้และการแชร์** ในหน้าเลือกงาน

ลิงก์ทุกชนิดเก็บเป็นแฮชในฐานข้อมูล ตัวจริงคืนครั้งเดียวตอนสร้าง และแสดงบนหน้าจอ
ให้คัดลอกส่งเองได้ เผื่อช่วงที่เมลยังไม่เปิด

## รหัสผ่านไม่วิ่งผ่านเมล

`docs/access.md` เขียนไว้ตั้งแต่ต้นว่าแอดมินเชิญด้วยอีเมลแล้วผู้ใช้ตั้งรหัสเอง
แต่ของจริงคือรัน `scripts/create_user.js` แล้วบอกรหัสชั่วคราวกันปากเปล่า
ตอนนี้เอกสารกับของจริงตรงกันแล้ว สคริปต์ยังอยู่สำหรับตอนตั้งระบบครั้งแรก
หรือตอนที่ยังไม่มีใครล็อกอินได้เลย

## เมลเตือนผู้ออกบูธ

กติกาที่บังคับในโค้ด

- **บริษัทหนึ่งได้ฉบับเดียว** รวมทุกงานที่ค้างไว้ในนั้น ไม่ใช่ 11 ฉบับตามจำนวนงาน
- **งานที่วันจัดผ่านไปแล้วไม่ส่ง** เลือกเฉพาะงานที่ `move_in_from` หรือ `start_date`
  ยังมาไม่ถึง และสถานะเป็น planning / selling / onsite
  ข้อนี้มีเพราะ `docs/exhibitor.md` เตือนว่าวันที่ในข้อมูลเป็นของรอบที่ผ่านมา
  ถ้าไม่กัน กำหนดส่งทุกงานจะเลยกำหนดหมดแล้วยิงเมลรวดเดียวถึงทุกราย
- **วันเดียวส่งซ้ำไม่ได้** เช็กจาก `mail_log` ย้อนหลัง 20 ชั่วโมง ไม่ใช่จำในตัวแปร
  เพราะบน Vercel แต่ละคำขอคือโปรเซสใหม่
- ส่งสำเนาถึงเซลล์เจ้าของดีลด้วย (`deal.owner_id`)

ดูก่อนส่งเสมอ

```
GET /api/mail/reminders/preview            ใครจะได้รับบ้าง (ไม่ส่งอะไรทั้งสิ้น)
GET /api/mail/reminders/preview?days=60    มองไกลกว่าปกติ
GET /api/mail/reminders/preview/:dealId    เปิดเนื้อเมลจริงเป็นหน้าเว็บ
```

## cron

ตั้งไว้ใน `apps/api/vercel.json` ให้ยิง `/api/cron/reminders` ทุกวันตี 2 (UTC)
Vercel แนบ `Authorization: Bearer $CRON_SECRET` มาให้เองเมื่อมีการตั้ง env ตัวนี้
ถ้าไม่ได้ตั้ง `CRON_SECRET` ปลายทางจะตอบ 503 ทุกคำขอ ดีกว่าเปิดให้ใครก็ได้สั่งยิงเมล

แผน Hobby ของ Vercel รัน cron ได้วันละครั้ง ซึ่งพอดีกับงานนี้
ถ้าย้ายไป Railway ให้ใช้ scheduler ของที่นั่นยิง URL เดิมพร้อม header เดียวกัน

## ข้อจำกัดที่ต้องรู้ก่อนเปิดใช้

**ฐานข้อมูลยังไม่มีอีเมลของผู้ออกบูธ** ตาราง `contact_person` ว่างเปล่า 0 แถว
และ `deal.owner_id` ว่างทุกดีล เมลเตือนจึงยังไม่มีปลายทางและสำเนาถึงเซลล์ยังไม่ทำงาน
ในไฟล์ต้นทาง `prototypes/app4.json` มีชื่อผู้ติดต่อ 80 ราย และอีเมล 23 ราย
ติดอยู่กับบูธ แต่ `apps/api/src/writeEvent.js` ไม่ได้เขียนลง `contact_person`
ต้องแก้ตัวนำเข้าก่อน เฟสเตือนถึงจะมีคนรับ

**การส่งจาก @penguinx.co ต้อง verify โดเมนใน Resend** ซึ่งต้องเพิ่มเรคคอร์ด DNS
ที่ Cloudflare ตอนนี้ยังเข้าบัญชีนั้นไม่ได้ โค้ดเตรียมไว้พร้อมแล้ว เหลือแค่ใส่ค่า

## ยังไม่ได้ทำ

- แจ้งเตือนเมื่อมีคนตอบคอมเมนต์ (`comment.author_email`)
- ยืนยันเวลาขึ้นเวทีให้วิทยากร (`person.email` + `session`)
- แนบไฟล์ในเมล และรับไฟล์อัปโหลดจากผู้ออกบูธ

## เรื่อง LINE

`contact_person.line_id` ส่งข้อความหาไม่ได้ LINE ไม่อนุญาตให้ส่งหาใครด้วย LINE ID
ที่พิมพ์เอง ต้องใช้ userId ที่ได้จาก Official Account ของเราเอง และคนนั้นต้องแอด OA
เป็นเพื่อนก่อน สำหรับผู้ออกบูธและผู้ติดต่อภายนอก อีเมลจึงเป็นช่องทางเดียวที่ทำได้ตอนนี้
