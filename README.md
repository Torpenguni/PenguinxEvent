# penguinxevent

แพลตฟอร์มจัดการงานอีเวนต์ของ PenguinX ใช้ภายในองค์กรเท่านั้น
ครอบคลุมตั้งแต่ขายบูธและผังงาน งบประมาณ สปอนเซอร์ การตลาด เวทีสัมมนา
ไปจนถึงการดูแลผู้ออกบูธและงานก่อสร้าง

งานที่รองรับ — Restech & Thailand Restaurant Conference · CafCon & Damn Expo
และงานย่อยอีก 5-6 งาน

## สแตก

ตามที่ทีมใช้อยู่แล้วใน `jeng-nai-kradaat` จะได้ไม่ต้องเรียนของใหม่

| ชั้น | ใช้ |
|---|---|
| หน้าเว็บ | React 18 + Vite |
| หลังบ้าน | Express + PostgreSQL (`pg`) + JWT |
| โครงโปรเจกต์ | npm workspaces |
| ขึ้นเซิร์ฟเวอร์ | Heroku |

## เริ่มใช้งาน

ต้องมี Node 20 ขึ้นไป และ PostgreSQL 14 ขึ้นไป

```bash
npm install

cp apps/api/.env.example apps/api/.env      # แล้วแก้ค่าใน .env
createdb penguinxevent
psql penguinxevent -f db/schema.sql -f db/seed.sql

node scripts/create_user.js you@penguinx.co "ชื่อคุณ" admin   # จะพิมพ์รหัสผ่านชั่วคราวออกมา

npm run dev            # api ที่ :4000, web ที่ :5173
```

### นำผังบูธเข้าระบบ

ทีมวาดผังด้วยการ merge ช่องใน Google Sheet อยู่แล้ว สคริปต์อ่านตรงจากตรงนั้น

```bash
python3 scripts/sheet_to_plan.py booking.md > plan.json
node scripts/load_plan.js restech-trc-2026 plan.json
```

## โครงไฟล์

```
apps/api/        Express + pg  ตรวจสิทธิ์ทุก endpoint
apps/web/        React + Vite
db/schema.sql    35 ตาราง 3 มุมมอง พร้อมสิทธิ์ตั้งต้น
db/seed.sql      งาน ประเภทบูธ หมวดงบ และเช็กลิสต์ผู้ออกบูธ
scripts/         สคริปต์นำเข้าและสร้างผู้ใช้
prototypes/      ตัวอย่างหน้าจอแบบไฟล์เดียว เปิดดูได้เลยไม่ต้องมีเซิร์ฟเวอร์
docs/            ที่มาของทุกการตัดสินใจ อ่านก่อนแก้สคีมา
```

## เอกสาร

| ไฟล์ | เรื่อง |
|---|---|
| `docs/plan.md` | ผลสำรวจตลาดและขอบเขต |
| `docs/schema.md` | ที่มาของทุกตาราง อ่านจากชีตจริง |
| `docs/sales-flow.md` | กระบวนการขายและการดูแลผู้ออกบูธ |

| `docs/feasibility.md` | ให้ตัวเลขงบวิ่งเอง และหน้าเป้ากับ run rate |
| `docs/stage.md` | โมดูลเวทีสัมมนา |
| `docs/access.md` | ตารางสิทธิ์และเหตุผลของแต่ละเส้น |

## หลักที่ยึด

**ตรวจสิทธิ์ที่เซิร์ฟเวอร์เสมอ** การซ่อนเมนูบนหน้าจอเป็นเรื่องความสะดวก ไม่ใช่การกันสิทธิ์
ทุก endpoint เรียก `require(module, level)` และคำสั่ง SQL กรอง `owner_id` เองเมื่อ scope เป็น own

**เก็บแฮช ไม่เก็บของจริง** ทั้งรหัสผ่านและ token ล็อกอิน เพิกถอนได้รายเครื่อง

**ปิดใช้งานแทนการลบ** ดีลเก่ายังต้องรู้ว่าใครเป็นคนปิด

**ทุกการเปลี่ยนสถานะลง `audit_log`** ทีม 15-20 คนแก้ผังเดียวกัน ต้องตามได้ว่าใครทำอะไร

## สถานะตอนนี้

ทำแล้ว — สคีมาครบ ล็อกอิน ตรวจสิทธิ์ หน้าเลือกงาน ผังบูธ เลื่อนสถานะ ปล่อยคืนคิว
และรายการที่ต้องตามมัดจำ

ยังไม่ได้ทำ — ดีลและใบเสนอราคา งบประมาณ เวที ผู้ออกบูธ และผลงานเซลล์
ทั้งหมดมีตัวอย่างหน้าจอครบแล้วใน `prototypes/platform.html`
